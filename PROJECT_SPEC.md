AIRIK — PROJECT SPECIFICATION

Master Brief, Content Strategy & Development Roadmap

Project: Airik
Repository: kavesmailey/airik
Production: airik-xi.vercel.app
Framework: Next.js 14.2.15
Deployment: Vercel
Language: Persian / فارسی
Direction: RTL
Primary Market: Iran
Business Type: Professional Printing House / چاپخانه
Current Status: MVP website is live, but content, hierarchy, spacing, UX, SEO and visual refinement require a major second phase.

⸻

01 — PROJECT PURPOSE

Airik is a professional printing house website.

The website should NOT feel like a generic local printing shop website.

It should communicate:

* professionalism
* technical expertise
* reliability
* production capability
* quality
* clarity
* modernity
* confidence

The website should make a visitor feel that Airik understands printing as a production system, not simply as a place where files are printed.

The site should serve three primary purposes:

1. Generate printing leads.
2. Explain printing services and techniques.
3. Build organic search traffic through useful, authoritative content.

The website should eventually become a combination of:

Printing Company + Printing Knowledge Base + SEO Content Platform + Lead Generation System

⸻

02 — IMPORTANT DESIGN DIRECTION

The current website has a functional structure, but the content and visual rhythm are too minimal.

The next phase should move toward:

* more breathing room
* larger vertical spacing
* stronger typography hierarchy
* richer content
* more editorial layouts
* more visual storytelling
* stronger service presentation
* stronger CTAs
* better information architecture

Do NOT solve the problem by simply adding random decorative elements.

The goal is:

More content + more whitespace + stronger hierarchy

not:

More content + visual clutter

⸻

03 — SPACING / LAYOUT PRINCIPLES

The current sections generally feel too compressed.

Increase vertical padding substantially.

As a general starting point:

Standard sections

Use approximately:

padding-top: 96px;
padding-bottom: 96px;

For important editorial sections:

padding-top: 120px;
padding-bottom: 120px;

For major hero sections:

padding-top: 140px;
padding-bottom: 120px;

These are starting values, not absolute rules.

The final spacing should be determined visually.

The website should feel calm and spacious.

Avoid stacking many sections with only 40–64px of vertical spacing.

22 — NEXT.JS SERVER / CLIENT RULE

The current project experienced this error:

Error: Event handlers cannot be passed to Client Component props.

This indicates a Server Component is passing functions such as:

onMouseEnter
onMouseLeave

to a Client Component.

Future development must respect the Server / Client Component boundary.

If interactivity is required:

* isolate it into a small Client Component
* add "use client" only where necessary
* do not convert the entire page to a Client Component unnecessarily

Prefer CSS hover states where JavaScript is not required.

For example, instead of:

onMouseEnter
onMouseLeave

prefer Tailwind/CSS:

hover:
group-hover:
transition-

where possible.

24 — CURRENT KNOWN TECHNICAL ISSUE: PERSIAN HEADER VALUES

The project previously produced:

TypeError: Cannot convert argument to a ByteString
because the character at index 1 has a value of 1583
which is greater than 255.

and:

TypeError: Cannot convert argument to a ByteString
because the character at index 1 has a value of 1608
which is greater than 255.

This indicates Persian/Unicode text was being inserted into an HTTP header.

HTTP headers should not receive arbitrary Persian strings directly.

Future code should inspect:

* headers.set(...)
* response.headers
* NextResponse
* fetch request headers
* middleware
* metadata-related response logic

before adding Persian values.

Persian text belongs in:

* HTML
* metadata
* JSON
* body content

not raw ByteString HTTP header values.
